# 资料库位置与 iCloud Drive 文件同步

2026-09-14。用户确认采用类似 Obsidian 的资料库文件夹体验后，在 `main` 接入本地位置切换及文件同步基础；无新分支、环境开关、Foldpin 云账号或服务端。真实 iCloud 双机验收仍待完成，不能把合成文件交换测试写成已验证的正式同步支持。

## 使用方式

设置新增「数据与存储」。

- **更改存储位置**：选择上级文件夹，在其中创建 `Foldpin Library`。可以选择 iCloud 云盘中的文件夹。复制并校验成功才切换；保留原文件夹。
- **打开已有资料库**：另一台 Mac 使用同一新版 Foldpin，选择 iCloud 云盘里的同一资料库文件夹。只打开，不把当前库合并进去。
- **旧库升级**：先识别旧格式，再经目标目录选择器创建新版副本，保留旧库。不会在任意选定目录初始化空纸片。
- **使用默认位置**：确认后自动打开默认库；旧格式在应用自己的默认存储区域自动升级并保留原文件，不再弹第二次升级确认或文件夹选择器。再次切回复用升级后的库，已在默认库时只提示当前状态。这仍表示打开默认库已保存的内容，不把当前库迁回或合并。
- 文件尚未下载完整、目录授权失效、目标冲突和中断恢复在此页面显示。长路径和错误可滚动查看。iCloud 的上传和跨设备到达时间由系统决定，应用不显示无法确认的「全设备已同步」。

迁移已共享的资料库后，其他 Mac 也须改为打开新位置；保留的原目录是旧副本，不会自动继续与新位置同步。

新设备收到的纸片默认在收纳里，不自动弹出到桌面。正文、附件、收藏、颜色、图标、集合和删除共享；位置、尺寸、置顶、折叠和桌面显示状态在每台 Mac 独立保存。这里借鉴的是文件夹同步体验；Foldpin 仍保存原生区块结构，Markdown / HTML 是既有导出格式。

## 文件格式

| 位置 | 内容 |
| --- | --- |
| `library.json` | 库 UUID、格式版本、最低读取代次、创建时间、首次建库所需的修订路径 |
| `revisions/notes/<纸片 UUID>/<修订 UUID>.json` | 不覆盖旧文件的纸片修订；包含父修订、日期及完整共享文档；空载荷表示彻底删除 |
| `revisions/collections/<集合 UUID>/<修订 UUID>.json` | 集合独立修订和删除记录 |
| `assets/` | 原图、预览、音视频、封面和文件附件；沿用既有资源路径 |
| `notes/`、其他旧文件 | 迁移保留下来的恢复材料，不是新版库当前内容的读取入口 |
| 应用支持目录中的 `FoldpinLocalState/` | 本机书签、迁移日志、目录锁、按库 UUID 保存的桌面状态；不迁入共享库 |

共享文档仍用既有 `NoteDocument` v2 编码；frame、pin、collapse、shelved 在共享载荷中使用固定默认值，本机桌面数据单独覆盖。`conflictOf` 标识冲突来源，收纳和集合显示「冲突副本」，不改写正文。

库格式当前为 1，读取代次为 3。升级副本中放置 `notes/requires-foldpin-3.json`，使旧版 `NoteLibrary` 在允许写入前拒绝识别该库。该门槛不能控制已经运行、持有旧内存的历史客户端；同一共享库应使用一致的新版应用。不要直接编辑或清扫 `revisions/`、旧 `notes/` 或删除记录。

## 保存、同步与冲突

`LibraryDisk` 通过 `NSFileCoordinator` 协调访问。每次共享修改写入新的 UUID 修订文件，原子落盘；窗口几何变化只写本机桌面文件。保存前复查库身份，目录被替换时不能把旧会话写入新库。

每 3 秒在后台检查活动共享库；录音、导入、组合输入和图片标题编辑期间延后应用外部内容。检查期间发生本地保存时丢弃旧快照，下次重新读取。只有修订发生变化才更新 Store 和收纳列表，空闲检查不重建编辑器或重排纸片。

iCloud 的文件到达顺序不保证一致。首次建库的基线文件、已知对象或父修订缺失时等待，不认作空库或删除。对未在本机就绪的附件请求系统下载，内容本身仍保留；资源到达后刷新图片和视频封面。设置中的提示不等于系统下载成功或远端已经收到。

两个离线设备从同一父修订写入不同内容时，两份文件都保留。应用按稳定的修订 ID 选出原纸片上的一份，其余不同内容生成确定 ID 的冲突副本，再写入合并修订。重复交换同一组修订不会不断生成副本；集合冲突同样保留副本，不擅自丢掉一方的成员关系。这里没有自动合并段落或协同编辑。

彻底删除使用持久删除修订。删除与离线编辑并发时，原条目保持删除，新编辑内容成为冲突副本。旧修订和共享资源目前不自动压缩或清理，因此应用内的彻底删除不等于对历史文件进行安全擦除，磁盘占用会随历史增长。后续清理不能让长期离线设备重新带回已删除条目。

## 迁移与会话

`LibraryLocationController` 管理目录授权、活动库和缓存；`LibraryRelocation` 在后台复制校验。切换位置前提交当前编辑、完成录音并保存，导入/导出未完成则阻止切换。随后设置全库写入屏障，暂停新增、编辑、集合和延迟文件操作；媒体释放旧路径的播放对象。

迁移在目标同一卷的独立暂存目录完成。流式复制全部安全普通文件，比较相对路径、大小和 SHA-256；复制后再次检查源，再从副本重新解码，检查资源引用。拒绝符号链接、自身/嵌套目录以及已有目标覆盖。目标就绪后再改名提升，验证书签，最后原子写本机 `location.json`：这是唯一的活动位置提交点。

提交前重启仍选原位置，提交后重启校验目标；目标不可访问时阻止空库初始化。迁移日志记录源、目标、暂存和校验值。已提升但未提交的目标只有在源和目标均仍匹配校验值时才可重试使用；否则保留两份并要求选择明确的资料库。取消只清理当前任务创建的暂存目录，不删除源或已有目标。崩溃遗留的暂存材料不会在启动时盲目删除。

`LibraryPath` 是 Store、NoteFile 和媒体模型共享的路径引用，迁移后原有引用写入新位置。同一资料库迁移保留原生编辑器、选区和 UndoManager；打开别的库缓存旧会话，切回时复用原 Store/窗口，并重新加载外部修订。外部内容作为可撤销更新进入同一个编辑器，不清空旧撤销链。安全作用域访问随相应会话保留，本机目录锁阻止另一个新版进程同时打开同一实际目录。

## 实现入口

- `Core/LibraryDisk.swift`：修订、确定性冲突副本、文件协调、下载和本机状态。
- `Core/LibraryRelocation.swift`：只读探测、完整复制校验、提交前恢复日志。
- `LibraryLocationController.swift` / `LibraryStorageSettingsView.swift`：目录选择、书签、切换与后台检查、双语设置。
- `Core/NoteFile.swift` / `NoteLibrary.swift` / `NoteStore.swift` / `NoteCollections.swift`：路径重新绑定、写入屏障和外部快照。
- `AppDelegate.swift` / `NoteEditor.swift`：编辑和媒体保存屏障、窗口会话缓存、外部内容更新。
- `Tests/LibraryStorageTests.swift`、`scripts/checks/LibraryWindow.swift`：临时库与不可见原生窗口验证。

## 验证边界

本机测试覆盖迁移保真、源保留、路径重新绑定、本机桌面隔离、离线双改、集合冲突、删除并发编辑、重复交换、部分下载、非法路径、缺附件、取消、完成目标重试和源变化拒绝重试、写入屏障、资料库身份替换及非法修订环。原生检查覆盖同一编辑器和两级撤销、目录互斥锁、书签保存与缓存切回，以及设置内容布局。

实际 macOS 沙盒中重启恢复权限、权限收回、iCloud 账号退出、磁盘满/断盘、每个进程崩溃时点、真实双机在线/离线交错修改和 iCloud 文件版本行为仍未验收。没有操作用户真实库、真实 iCloud 目录或通用剪贴板，也没有启动已安装的 Foldpin。

原 [18 项验收方案](library-location-and-sync-plan.md#9-验收清单) 继续作为正式交付门槛；合成测试只覆盖其中列出的数据和会话行为，不代替这些实机故障场景。网络盘不支持；外置盘和第三方同步服务没有兼容性承诺。

### 2026-09-14 默认位置入口修复

用户实测指出「使用默认位置」又要求选择升级目标。原入口错误地调用了需要用户授权外部目标的通用升级分支。现在 `openDefaultLibrary()` 自动找到默认资料库；旧 `Foldpin` 的升级副本保存在同一应用支持目录的 `Foldpin.library`，旧目录保留。该默认入口直接提供应用拥有的升级目标，省去第二次升级对话框和目录选择器。之后优先打开已升级副本，已有新修改不会因再次切回而被旧文件覆盖。未完成迁移仍使用原有日志/校验恢复规则，不绕过目标冲突检查。

新增定向原生测试覆盖：从自定义库回到旧默认库、全程无目录选择、源文件不变、两库内容不合并、修改默认库后反复切回保留同一 Store，以及已在默认位置时不重复升级。测试通过；这次不涉及真实资料迁移。
