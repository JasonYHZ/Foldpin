# Foldpin 原生块编辑器：实施记录与路线

日期：2026-09-08。用户明确选择原生路线，关注桌面上多张纸片同时常驻时的资源开销。此前 WKWebView + Tiptap 候选提案已被此次决定取代。

第一阶段代码已接入现有单纸片工程。本文区分当前能力与后续范围，不代表完整 Notion 编辑器或多纸片 MVP 已完成。没有引入 WebView、JavaScript 运行环境或第三方编辑器依赖。

## 技术与数据

- 纸片窗口、玻璃表面、标题栏、菜单栏与设置保持原生实现。
- `PaperTextView(usingTextLayoutManager: true)` 显式使用 TextKit 2；一个连续编辑区域承载正文、标题、清单、代码和图片。没有为每段文字创建独立 TextEditor。
- `NoteContent` 是版本化块文档，块包含稳定 UUID、类型、文字、行内粗体 / 斜体、勾选状态、代码语言或图片元信息。
- `BlockTextCodec` 在结构化内容与 NSTextStorage 之间转换。字体、颜色和列表标记从块模型生成；图片原始文件不进入 JSON。
- 原生文本输入与结构命令共用 NSTextView 的 UndoManager。文本通知和系统 undo / redo 完成通知负责同步文档与自动保存；语音接入后也必须加入此流程。
- 组合输入期间读取草稿但不替换文本或样式；收纳前结束组合输入后提交结构化文档。语言只更新界面文案，外观只更新样式。

## 第一阶段可操作内容

| 操作 | 入口与行为 |
| --- | --- |
| 转换 / 插入内容块 | 空段落输入 `/` 显示不抢输入焦点的建议浮层；Backspace 可删除，↑ / ↓ 选择、回车确认、Esc 关闭。底部「+ 内容块」与右键保留显式菜单 |
| 基础内容 | 正文、一级标题、二级标题、项目列表、待办、引用、代码块、图片 |
| Markdown 输入 | 段落行首 `#` / `##`、`-` / `*` / `+`、`[]` / `[ ]` / `[x]`、`>` 加空格转对应块；三个反引号可带代码语言，加空格或回车转代码块；可撤销 / 重做 |
| 行内格式 | 选中文字后 ⌘B 粗体、⌘I 斜体；也可打开内容块菜单 |
| 待办 | 点击复选标记或菜单切换完成状态；回车继续待办，空待办回车退回正文 |
| 标题 | 回车拆分后继续普通正文；退格与跨段选择沿用原生文本行为 |
| 块排序 | 菜单上移 / 下移，或 ⌘⌥↑ / ⌘⌥↓；支持复制当前块 |
| 代码 | 等宽显示、基础词法高亮；菜单选择纯文本、Swift、JS / TS、Python、JSON、SQL、Shell；菜单可保真复制代码；⌘Return 退出代码块 |
| 图片 | 选择文件、粘贴图片或拖入一张图片；原图与预览先写入本机，再插入文档；追加普通段落方便继续输入 |

底部按钮显示当前块类型，代码状态下提示 ⌘Return 回到正文。删除整张纸片全部字符后开始空正文；主动创建的空标题 / 代码及撤销恢复的类型不受影响。空代码或空标题按 Backspace 退回正文。光标移动与输入时按目标块设置字体、颜色与元信息，避免代码背景污染相邻普通段落；显式转换代码块不删除其字面 `/`。新文件保持真正空白，重开则恢复已有内容和类型。

代码高亮是有长度上限的轻量词法着色，不是完整语法分析器；复杂转义、嵌套语法等可能无法精确着色。超过 24,000 UTF-16 单位的代码块保留等宽显示，跳过高亮以免阻塞输入。代码不会运行。

2026-09-08 增加 GitHub 风格明暗配色；关键字 / 字符串 / 注释 / 数字 / 函数名用一次有序词法扫描着色，网址中的注释标记保留字符串颜色。代码面板由 TextKit 2 `enumerateTextSegments` 的实际文字几何绘制，支持软换行和空代码块；背景不进入字符属性、剪贴板或 JSON。首末行留白与水平内边距由显示样式提供。参考 [GitHub 官方主题](https://github.com/primer/github-vscode-theme)，随应用保留 MIT 许可；没有载入 CSS、JavaScript 或外部网页。

设置中的跟随系统 / 明亮 / 暗色与纸感 / 通透独立。`ThemeSettings` 同步更新应用的 NSAppearance，动态颜色沿原视图层级解析；删除旧纸感强制明亮的覆盖。组合输入期间不重写属性，现有斜杠浮层也更新明暗。`usesAdaptiveColorMappingForDarkAppearance` 关闭，避免 AppKit 再次映射已提供的暗色配色。

图片支持 PNG、JPEG、HEIC、TIFF 文件和剪贴板图像；限制 40 MB / 8000 万像素，后台生成最长边 1400 像素的预览。纸片中按宽度适配、保持比例，过高图片限制展示高度。导入过程记住目标块 UUID，不跟随后来移动的光标；目标删除或正在组合输入时提示重新插入。

Markdown 快捷方式只匹配光标前、逻辑段落开头的短前缀，支持连续输入 `- [ ] ` 从列表转待办。转换去掉前缀，保留块 ID、后续正文与可用行内格式；代码块清除行内粗体 / 斜体。`MarkdownBlockShortcut` 只描述现有块类型的输入规则，不解析整个文档。粘贴、拖放、恢复旧笔记、句中输入、选区替换、已有代码及输入法组合期间均不触发。空文档的块元信息随结构操作加入同一个原生 UndoManager，待原生文字 undo / redo 完成后恢复，避免重做空标题或空代码块时丢失类型。

当前块排序通过菜单与键盘实现，未做可视拖拽手柄。H3–H6、有序 / 嵌套列表、表格、链接交互、图片图注 / 原图预览、行内 Markdown 自动转换、完整 Markdown 导入 / 导出和语音尚未接入。外部富文本粘贴按纯文本处理，不加载外链图片；Foldpin 内复制粘贴保留受支持的块与标记。

## 本地保存与迁移

`note.json` 升级为 v2，`content` 是唯一正文来源。首行标题和收纳摘要从内容派生，窗口位置、置顶、折叠及收纳字段保持原有语义。

1. 读取 v1 时只在内存把原文按换行转为普通段落，保留 CRLF、空行、缩进、Unicode 与字面 Markdown。
2. 首次保存 v2 前，在 `backups/note-v1-<UUID>.json` 保存原文件的完整字节；备份不可覆盖，失败时停止迁移。
3. 编码并验证 v2，确认所有图片引用有对应文件，然后原子替换 `note.json`。
4. 未来 schema、未知块类型、无效内容或布局均阻止覆盖；已有保存失败处理继续保留内存内容和窗口。

附件放在同级 `assets/<UUID>.original` 与 `assets/<UUID>.png`，路径只由 UUID 生成。删除或撤销插入图片不立刻清理文件，防止重做与备份引用失效；未引用文件清理是后续任务。用户原来的沙盒笔记没有在开发验证中被读写；迁移在运行新版并首次保存时发生。

## 多纸片性能约束

本阶段通过原生编辑器避免每张纸条维护 Web 页面和脚本运行环境。普通输入会扫描当前纸片的块结构；样式只更新变化的块，高亮只处理变化的代码块。这里只对实现路径作说明，不宣称已测出特定内存 / 延迟优势。

- 每个编辑器的缩略图缓存限制为 16 MB，原图不常驻显示。
- 折叠继续保留同一编辑器、选区和原生撤销栈，避免此次升级破坏原有承诺。
- 收纳后的编辑器卸载需要先独立保存会话历史，尚未实施。
- 当前应用仍只维护一张纸条，尚未获得 10 / 30 张纸条同时显示、玻璃合成或内存占用的实测数据。
- 多纸片阶段再集中测量展开、折叠、收纳、快速恢复与图片缓存，届时决定共享缓存及休眠策略。

## 语音后续接入

沿用此前暂定体验：以说话转文字为主，可选保留录音。识别语言与界面语言分开。

下一阶段验证 Apple `AVAudioEngine` 与 `SpeechAnalyzer / SpeechTranscriber`：查询设备、语言和模型状态，按需下载模型，明确麦克风权限与离线边界。当前未增加麦克风权限、未下载模型或启动录音。

转写草稿独立显示，停止并确认后作为一次可撤销插入；不反复覆盖正文。异步插入位置需要维护块 ID 和位置映射；目标删除时保留草稿，让用户重新选择位置。失败、取消与退出应停止采集，可选音频沿用附件文件存储。

## 验证与后续

本轮只做构建及隔离数据 / 无可见窗口的原生编辑器检查，记录见 [原生编辑器验证](native-editor-validation.md)。不反复唤起或调整用户的应用。

必要检查包括 v1 字节备份、迁移失败保护、v2 重启恢复、图片文件先写后引用、原生块拆分与撤销 / 重做、代码换行、末尾空块身份以及原有保存 / 窗口状态测试。实际中文 IME、真实菜单和拖放、双语排版、玻璃 / 焦点及多窗口资源仍需集中体验确认。

后续顺序：完成首轮原生交互反馈 → 可视块拖拽及图片体验 → 语音捕捉 → 多纸片与休眠策略。按用户实际反馈调整，不以本轮实现宣称完整体验验收。
