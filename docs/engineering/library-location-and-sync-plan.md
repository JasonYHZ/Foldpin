# 自定义资料库位置与 iCloud Drive 同步开发方案

日期：2026-09-14

状态：开发方案，未实现；依据用户确认的“用户选择存储位置，未来可放入 iCloud Drive 跨 Mac 使用”方向。本文不代表同步已经可用。

## 1. 目标和阶段

让用户掌握整个资料库的存储位置，能可靠迁移，也能在另一台 Mac 打开已有库。应用继续本地优先，不要求 Foldpin 账号或官方服务器。

| 阶段 | 交付 | 出口 |
| --- | --- | --- |
| S1 | 本地自定义目录、可靠迁移、打开已有库、权限和错误恢复 | 单机验收通过，可作为独立版本交付 |
| S2 | 共享数据与设备状态分离、外部变化检测、并发写入保护 | 两个隔离实例通过冲突和故障测试 |
| S3 | iCloud Drive 文件下载、版本冲突与删除传播 | 两台真实 Mac 通过线上、离线及交错编辑验收后，才声明支持同步 |

S1 对已识别的 iCloud／其他云提供商目录暂不启用写入迁移，解释“该位置的同步支持正在准备中”，不把警告当成并发安全机制。检测无法覆盖所有第三方同步工具，文档明确 S1 仅支持非共享本地目录。S3 才开放已验证的 iCloud Drive 路径。外置磁盘须通过断连测试后纳入支持；网络盘和其他云盘不默认支持。

本轮不加入自动定时备份、云账号、团队协作、iPhone 客户端或 AI。迁移保留源文件属于失败恢复措施，不包装成备份产品。

## 2. 当前工程事实

- `Core/NoteLibrary.swift` 默认从 Application Support/Foldpin 加载，保存 `notes/<UUID>.json`、共享 `assets/` 和迁移标记；`directory` 当前为不可变值。
- `Core/NoteStore.swift` 持有不可变 `NoteFile`，有延迟自动保存及错误保护。不能只改偏好后让旧保存任务继续写源目录。
- `Core/NoteFile.swift` 集中生成图片、音视频、附件路径。`NoteEditor.swift` 及媒体／镜像闭包也可能捕获旧路径，必须一并处理。
- `AppDelegate.swift` 持有资料库，`ShelfView.swift` 持有资料库与单独的 `NoteCollections`；集合路径绑定于原目录。
- `NoteDocument` 同时保存正文、收藏、颜色、删除状态和 frame/isPinned/isCollapsed/isShelved。共享整个 JSON 会使桌面操作与另一设备正文编辑争用同一文件。
- 当前 `NoteLibrary.reload()` 复用旧 Store，并保留磁盘上消失的已有条目；它是重试读取机制，不是同步刷新机制，不能直接作为外部变更处理器。
- 当前彻底删除直接移除纸片 JSON、保留共享资产，没有跨设备删除记录。

以上是源码核对，不是新增构建或双机验证结果。

## 3. 设置与用户流程

在原生设置增加“数据与存储”，中英同步。显示当前路径和可理解的状态，提供：

1. **在访达中打开**：定位当前资料库。
2. **更改存储位置…**：选择父目录，创建独立 Foldpin 资料库子目录，迁移当前整个库。
3. **打开已有资料库…**：选择已存在的库，校验后切换；不与当前库合并。
4. **使用默认位置…**：复用同一迁移流程；默认目录已有旧库时，不覆盖，提供打开已有库或取消。

迁移前显示源、目标和迁移说明；迁移中显示进度和取消入口，短暂提交阶段不可取消。成功提示旧目录仍保留，可在访达查看，不主动删除源目录。

目录不可用时显示“资料库暂时不可用”，提供重试、重新授权、选择其他已有库；不能静默回落默认库或创建空笔记。只有用户明确选择新建资料库，才创建新库。

一次只打开一个资料库，不扩展成多库标签页管理器。切换到不同库前保存当前会话；原库已保存的控制器和撤销历史保留在本会话缓存中，切回可恢复。该缓存以后若要限制内存，必须另定不丢撤销的策略，不能在本任务中偷偷清空。

## 4. S1：位置、授权与资料库身份

建议新增职责边界（名称可在实现时调整）：

| 模块 | 职责 |
| --- | --- |
| LibraryLocationStore | 默认／自选位置、书签、过期更新、待提交位置；保存在本机应用私有目录 |
| LibraryAccessSession | 安全作用域访问的开始／结束、目录身份与读写能力校验 |
| LibraryManifest | `library.json`：库 UUID、格式版本、最低可写格式、创建时间 |
| LibraryRelocationCoordinator | 迁移状态机、取消、恢复日志、复制与校验、提交／回滚 |
| LibrarySessionCoordinator | 活动库切换、保存屏障、路径重新绑定、旧任务失效保护 |

使用系统目录选择器和 security-scoped bookmark；不只保存路径字符串，不硬编码用户 iCloud 路径。书签和授权只留本机，不随库迁移。重新启动后恢复访问，失效则请求重新选定；具体 entitlement 按实际签名与沙盒配置核对。

资料库打开必须先只读探测，再决定加载或升级，不能在任意目录调用当前会自动创建 notes/空纸片的初始化。旧库没有 manifest 时检查既有布局与文档版本，在原子写入 manifest 前保留升级恢复材料；未识别、损坏、新版本不支持的库不自动修复或覆盖。未知文件保留；库内符号链接、路径穿越或资源越界拒绝自动迁移并显示原因。

库 UUID 标识逻辑资料库；迁移副本保持 UUID。单机同时打开原件和迁移副本时须用实际目录身份及本机活动记录区分，避免双写。本机进程锁只用于同机互斥，不宣称能协调断网的多台 Mac。

## 5. S1：迁移事务

状态：空闲 → 检查 → 完成编辑 → 复制 → 校验 → 提交 → 完成；任一步失败进入可重试状态。

1. 校验目标权限、可用空间、名称冲突及目录关系。拒绝目标为源自身、源的子目录、会覆盖已有内容的目录及等价路径别名。
2. 提交 IME、表格输入、图片标题，完成录音并保存；等待现有导入、导出等文件任务结束或安全取消。任一保存失败则不迁移。
3. 建立全库写入屏障，暂停新建、编辑、删除、集合操作、位置写入和后台落盘；保留原编辑器、选区及 UndoManager。媒体停止访问旧文件。复制期间不能边改源边复制。
4. 在目标同一卷的独立暂存目录复制整个库，含正常及已删纸片、所有资源、集合、迁移标记、空库标记、历史备份和其他安全普通文件。分块处理媒体，避免整库载入内存。
5. 检查文件清单、字节数和流式校验值，并用现有解码器检查结构和资源引用；不得将源库本来已有的缺失资源冒充迁移成功。发现问题保留源并说明。
6. 在目标卷内完成暂存目录改名，形成完整目标。跨卷不使用“移动即原子”的假设。持久化本机迁移日志，记录源／目标身份和阶段。
7. 先保证目标授权可重开，再事务性切换偏好和所有路径消费者。为延迟写入、导入回调及媒体加载增加会话代次校验，旧任务不得写任一错误目录。
8. 恢复输入并验证当前编辑器、UndoManager 和选择不变；迁移同一库不得重建正文。确认当前保存实际落到新目录后完成日志。
9. 取消仅清理由本事务创建且能确认归属的暂存文件；源和既有目标保持。源目录成功后仍保留，不自动清扫。

偏好、文件系统与内存无法组成一个系统级原子事务，需要恢复日志明确提交点。崩溃重启时：提交前选源；提交后先校验目标。目标不可访问时进入恢复界面，不自行把两份库合并或轮流写入。提交前存在完整目标副本也不代表可以忽略源的新状态。

## 6. S2：共享数据与本机桌面分离

以下为同步格式提案，需先做旧格式迁移测试，再冻结 schema。

| 共享资料 | 本机资料（按库 UUID 与本机身份保存） |
| --- | --- |
| 正文、块 UUID、媒体引用、颜色、图标、收藏、创建／修改时间 | 窗口位置和尺寸、置顶、折叠、桌面／收纳状态 |
| 集合及成员关系、软删除、同步版本与删除记录 | 搜索草稿、选区、UndoManager、播放进度、主题、快捷键、目录授权 |

“已收纳／桌面上”在各 Mac 独立；其他设备新增的纸片默认进入本机收纳，不自动弹窗。软删除作用于整个共享库，区别于只在本机收纳。旧窗口状态只在首次升级设备导入本机状态，另一台设备不套用旧屏幕坐标。

新格式必须让旧版本拒绝写入，而不只是添加一个旧客户端看不懂的可选字段；评估提升文档版本及库可写版本门槛，防止旧版本把被分离的状态重新写回。

外部文件变化通过协调读写及文件呈现／观察机制接入，回到前台时补查，事件合并与去重。文件系统事件仅是检查信号，不能直接等同于完整且最新的远端修改。

每个可变共享对象保留修订身份、父修订和设备来源。保存前与已读基线比较；检测旧基线时保留双方版本，不按修改时间简单选胜者。单纯比较再写入无法阻止两台离线设备同时写入，因此还必须验证 iCloud 冲突版本捕获，并在本机持久保存待同步修订恢复材料。

无本地改动时外部更新可应用于现有 Store／编辑器，不重建会话；有本地输入、录音、导入或未完成保存时先保留本地分支。对现有撤销链不得直接替换 document：需专门验证可撤销的外部更新事务；不兼容时保留当前分支及冲突副本，不能让旧撤销覆盖唯一远端版本。

集合也是共享可变对象，不能只保护纸片。首版冲突保留两份集合定义／待处理版本，不依靠整个 collections.json 的最后写入覆盖解决成员增删冲突。

## 7. S3：iCloud Drive 支持

先以用户选定的 iCloud Drive 普通目录开展两台 Mac 技术验证；系统 iCloud 容器属于另一接入路径，不在未验证时混为一谈。签名权限、文件协调、下载状态和版本 API 在此路径上的实际表现是前置验证门槛。

- 调用公开文件协调 API，读写／改名／删除遵守协调；不要在主线程等待下载或进行大文件扫描。协调器不是跨设备数据库事务。
- 识别尚未下载、下载中、不可用、冲突和真实缺失；保留纸片与附件占位。纸片 JSON 本身未下载也不能被认为是空库。
- 已完整下载的内容允许离线编辑；尚未取得的内容不新建空文件覆盖。待发送修订保留在本机，权限或网络恢复后再检查并提交。
- 一个目录内多个文件不保证同时到达。库 manifest、笔记和附件顺序任意时仍保持可恢复状态；必要时记录每次修订的资源清单及完整性信息。
- 冲突展示两份内容及来源、时间，用户可保留两份或明确选择版本。只有持久保存双方后才标记系统冲突已解决；失败不丢弃版本。冲突副本创建要幂等，不因事件重放重复复制。
- 软删除写入版本化删除状态；彻底删除在同步库中需持久删除记录（tombstone），并改造当前直接 unlink 的实现。离线设备持有旧正文时不无条件复活；若存在新编辑，保留为恢复副本并提示。
- 首版不自动过期删除记录，不跨设备回收共享附件。永久删除不等于安全擦除，系统历史和本机恢复材料应在产品说明中准确区分。
- 同步状态只显示系统能证明的程度，例如“已保存到本机”“正在下载”“需要处理冲突”；不能凭本地写成功显示“所有设备已同步”。

如果公开 API 在普通 iCloud 目录无法可靠保存并发现并发修订，停止放行 S3，改进文件协议（例如不可变修订文件）或重新评估系统容器方案；不通过“请勿同时编辑”替代冲突保护。

## 8. 开发任务与依赖

| 任务 | 内容 | 依赖／完成证据 |
| --- | --- | --- |
| T1 | 目录访问、manifest、只读探测、启动恢复 | 临时库测试＋真实签名下书签重启验收 |
| T2 | 写入屏障、任务代次、统一路径上下文 | 迁移后撤销／媒体／集合不写旧目录 |
| T3 | 复制校验、提交日志、取消和崩溃恢复 | 故障注入覆盖所有提交边界 |
| T4 | 设置页面、迁移和打开已有库流程 | T1–T3；双语、键盘与真实目录选择器验收 |
| T5 | 共享格式升级、本机窗口状态 | 旧数据保真、旧客户端不能误写 |
| T6 | 外部更新、修订冲突、集合及删除协议 | 两实例离线分支和乱序事件测试 |
| T7 | iCloud 路径技术验证、下载与系统冲突集成 | T5–T6；真实双 Mac，失败则不放行 |
| T8 | 文档、支持范围、发布说明 | S1 和 S3 分别记录，不能提前宣布同步 |

先交付 T1–T4；T7 的最小 API 探针可提前做以发现路线风险，但不连用户真实资料库。实现前再次读取最新 AGENTS.md 和源码，保留其他开发中的变更。

## 9. 验收清单

所有数据测试使用临时库；两台 Mac 使用专用测试库。未经明确授权不移动或删除用户真实资料，不更改其 iCloud 账号设置。

| 编号 | 场景 | 通过条件 |
| --- | --- | --- |
| L01 | 默认库升级 | 正文／附件／集合／最近删除／空库状态保真，失败不覆盖 |
| L02 | 迁移本地库 | 清单及校验一致；之后编辑仅写新目录；源完整保留 |
| L03 | 活动编辑迁移 | 中文组合输入、表格、标题、录音完成且保存；同一编辑器及撤销；失败留原库 |
| L04 | 导入／导出进行中 | 正确等待或取消，过期回调不写旧路径 |
| L05 | 取消／磁盘满／断盘 | 不留下已切换但不完整的活动库，不覆盖目标已有文件 |
| L06 | 每个提交点崩溃 | 重启选择正确库或提示恢复，不静默空库／双写 |
| L07 | 授权与路径变化 | 重启、书签失效、目录移动／改名、权限收回均可恢复 |
| L08 | 打开其他库 | 不合并；错误／未知版本拒写；切回原库保留本会话撤销 |
| L09 | 非法目标 | 自身／嵌套／等价路径、链接、非库、已有目录均按规则拒绝 |
| L10 | 大库迁移 | 至少千张混合纸片和大媒体；后台分块、界面可响应、取消生效；记录设备和实测值 |
| S01 | A 新建、B 收到 | 正文与附件可读，B 默认收纳、不套用 A 窗口位置 |
| S02 | A/B 同时及离线编辑 | 双方内容均可找回，冲突不重复，不能靠时间戳丢弃一方 |
| S03 | 外部更新＋本地撤销 | 不丢选区和原撤销，不以旧撤销覆盖唯一远端版本 |
| S04 | 纸片／附件乱序下载 | 等待与失败可区分，无空白覆盖、假删除或丢图 |
| S05 | 集合双向增删 | 双方变更保留或进入冲突处理，成员不静默丢失 |
| S06 | 删除＋离线编辑／恢复 | 删除记录有效；新离线内容可恢复；不无限复活 |
| S07 | 重放／退出／断网 | 操作幂等，重启能继续处理；不误报全设备同步 |
| S08 | 跨版本 | 不兼容客户端拒写，升级失败可恢复 |

单元测试、合成事件和离屏检查不替代系统目录授权、iCloud 双机同步、真实鼠标或多屏体验。S1 未完成 L01–L09 不交付；L10 必须记录可支持规模。S3 未完成 S01–S08 的真实双机关键场景，不开放正式同步承诺。
