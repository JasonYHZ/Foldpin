## 现状与证据边界

本轮检查 FoldpinSettingsView、AppearanceSettingsView、CodeThemeSettingsView、GeneralSettingsView、LibraryStorageSettingsView、ShortcutSettingsView 和 NoteAppearance。当前桌面运行实例显示早期纸片界面及读取失败，与源码版本不一致；没有重试读取或修改用户纸片。本方案不是当前构建的截图审阅结论，最终排版需用隔离数据运行新版验收。

确定的源码问题：

- 当前五个标签为通用、外观、快捷键、数据与存储、连接 AI 工具。新增编辑偏好和 AI 服务后，顶部标签会继续增多。
- 外观页混合材质大预览、主题、代码主题及语言，用户难以按任务寻找。
- 外观／快捷键固定约 556×720，存储约 560×460，各页面自定窗口尺寸，不利于统一布局。
- 通用页主要是登录启动、帮助、版本；语言实际在外观页，信息分类不一致。
- 当前纸片颜色是逐张操作；默认字号、默认颜色、默认尺寸等没有统一新建偏好。
- 代码背景透明度已有设置；不能把它当成整个纸片背景透明度。玻璃的阅读底色目前有固定值，未见可调模糊半径设置。

## 一、设置骨架

保留唯一 SwiftUI Settings scene，改为左侧分类、右侧内容的普通原生设置窗口。统一初始约 860×660 pt、最小约 740×560 pt，左侧约 180–210 pt，内容区独立滚动；尺寸为设计起点，不是苹果强制数值。

右侧统一页面标题、简短说明、Form 分组、系统控件。常规页面只保留一份标题，去掉宣传式大标题和重复“已保存”文字。外观保留一个紧凑合成纸片预览；不为每个选择做大型展示卡。窗口级布局负责尺寸，各子页面移除固定 frame(width:height:)。

设置立即保存。需要实际操作的迁移、导入、授权继续使用明确按钮；不增加全局“保存设置”。页面末尾只恢复本页普通偏好，恢复动作不能撤销授权、清理文件、改变库位置或登录项注册。

建议分类：

| 分类 | 内容 | 首轮处理 |
| --- | --- | --- |
| 通用 | 语言、登录时启动、启动行为 | 移入语言；保留真实系统登录状态 |
| 外观 | 明暗主题、纸感／通透、材质调整与预览 | 精简现有页；补齐有效材质参数 |
| 纸片与编辑 | 新建默认值、阅读排版、粘贴行为、标题栏显示 | 新增真实偏好与入口 |
| 快捷键 | 窗口内／全局快捷键、冲突提示、恢复默认 | 复用现有逻辑 |
| 数据与存储 | 库位置、切换／迁移、空间占用、大附件定位 | 统一排版，不改变数据流程 |
| AI 服务 | API 服务配置、默认模型、未来 Agent 服务 | 随 AI 会话阶段上线，未实现前不显示空页 |
| 外部 AI 连接 | MCP 启停、地址、客户端与权限、调用状态 | 现有“连接 AI 工具”更名，避免与 API 混淆 |
| 关于与帮助 | 图标、版本、使用说明、反馈、第三方许可 | 从通用拆出 |

尚无购买实现时不放虚假的订阅／账户入口。以后将已购状态与恢复购买加入“关于与帮助”或独立购买页，按真实流程决定。

## 二、必须区分三种设置作用范围

1. 应用显示偏好：主题、材质、默认阅读字号等，只影响本机显示，不改正文和 modifiedAt。
2. 新建默认值：颜色、置顶、窗口尺寸等，仅在用户新建空白纸片时应用；不批量覆盖现有纸片。复制纸片保留原值，导入保留已有元数据，没有元数据时才用默认值。
3. 单张纸片属性：现有颜色、图标、置顶、折叠等继续在纸片自身操作；设置页说明入口，不将全局设置悄悄改成当前焦点纸片设置。

本机偏好不放进共享库。同步来的纸片不能因另一台机器的默认设置被重写。恢复默认不清空用户数据。

## 四、透明度与模糊度的处理

用户希望颜色、透明度和模糊度可定制，必须拆开落实：

- 代码块背景透明度已经有真实实现，保留。
- 纸片通透模式可以先研究可控的阅读底色覆盖强度，不用整个 NSWindow.alphaValue 让文字与按钮一起变淡。纸感不显示通透专属控制。
- 原生玻璃模糊由系统材质管理。当前代码没有可设置的模糊半径，不能添加无效“模糊度”滑杆，不能使用私有 API。
- 若需要“柔和／清晰”等档位，必须先证明公开 API 或合成方案有稳定效果，再发布；不要仅改变透明度却命名为模糊度。
- 减少透明度／增强对比度开启时回退实色并说明系统设置优先；不可用控件解释原因。

预览和真实纸片必须共用同一参数模型、配色及渲染逻辑。调整预览不能读取用户正文，使用合成内容。参数高频变化合并刷新，不反复重新创建玻璃或编辑器。

## 五、AI 设置与 MCP 设置的分工

AI 服务：“让 Foldpin 使用你的 AI”。复用 ai-conversation-plan.md：协议、完整 URL、Keychain 凭据、模型、连接测试、默认服务；外部 Agent 服务只展示已验收适配器。

外部 AI 连接：“允许其他 AI 工具操作 Foldpin”。保留 MCP 已有默认关闭、逐客户端凭据、库范围、权限与本机审批。协议、端口等放连接详情；常态先展示连接状态和已授权客户端。

两者不能共用一个模糊的“启用 AI”总开关。关闭 MCP 不禁用内部 API 聊天；切换 AI 模型不改变外部客户端权限。

## 六、实现顺序

S1 设置结构重排：新分类导航、统一尺寸与表单、语言移到通用、代码设置独立分组、帮助版本移出。仅移动已有控件，保留偏好 key 和原行为。

S2 新建偏好与编辑偏好：建立类型化 NoteDefaultsSettings / EditorPreferences（建议名称），未知值回退当前行为。检查所有创建来源：快捷键、菜单、收纳、录音、导入、复制、MCP；明确默认值适用边界。添加正文字号需要先检查原生字体生成与布局缓存入口。

S3 外观增强：标题栏常显、通透阅读底色强度与真实预览；保持一个玻璃表面、动态颜色、可访问性回退和现有阴影。

S4 AI 配置随真实功能加入。设置搜索和自定义字体／色板后续再补。

每阶段分别提交可验收结果，不同时改数据存储和编辑器生命周期。当前任务交付整理方案，不将所有 P1/P2 设置视为已经实现。

## 七、验收

- 当前设置全部可从新分类到达，中英文无截断；页切换窗口不忽大忽小，无双重滚动条。
- 设置入口、⌘逗号、快捷键设置跳转和 MCP 设置入口仍定位正确。
- 旧偏好完整迁移或原键继续使用，升级不重置主题、语言、快捷键、权限和库位置。
- 新建默认值不更改旧纸片；复制、导入和 MCP 创建的规则与文档一致。
- 字号／行距更新后中文输入、选区、UndoManager、表格活动单元格与附件命中保持正确；不修改正文文件。
- Markdown 两种开关互相独立，关闭后原生纯文本粘贴／输入可用；代码块内不会误转换。
- 玻璃预览与真实窗口一致，文字不随背景变淡；没有伪模糊控件或私有 API。
- 恢复本页默认不改变系统登录授权、MCP 客户端、API Key、存储或数据。
- AI 未实现不显示假功能；未配置不影响普通纸片。
- 使用隔离测试数据和新版签名应用完成各页明暗截图、键盘与 VoiceOver 检查；读取失败的生产实例不作为新版验收载体。
