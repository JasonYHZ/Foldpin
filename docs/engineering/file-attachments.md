# 普通文件附件

2026-09-14 按用户要求接入。访达复制一个或多个普通文件后，在纸片正文按 ⌘V；也可拖入正文，或从原生「插入」菜单选择「导入附件…」。桌面纸片与收纳右侧共用同一个编辑器及撤销历史。

## 行为

- 区块显示文件名、大小和文件图标。双击用系统默认应用打开；区块右键提供打开、导出以及既有复制 / 副本 / 移动 / 删除。
- 导入在后台复制原始字节；每批最多 32 个文件，合计不超过 512 MiB。支持空文件，不支持文件夹、应用包和符号链接。
- 单个图片、受支持的音频 / 视频仍由原有媒体导入处理；多个文件作为普通附件批量插入。原生「导入附件…」可明确按普通文件导入媒体。
- 批量插入是一次正文变更，可撤销 / 重做。插入位置是当前块后方，空正文块会被替换；导入过程中目标块被修改 / 删除时拒绝插入并清理本批临时文件。
- 纸片保存失败时保留已插入内容和附件文件供重试；删除 / 撤销不清理资产，避免破坏恢复。
- 表格单元格继续只接受文字；没有加入附件斜杠菜单、文件夹打包、云上传或文件内容索引。

## 存储和复制

`NoteBlockKind.file` 与可选 `NoteBlock.attachment` 保存 UUID、原文件名、字节数；旧笔记缺省无附件，沿用 JSON v2 / schema 1。名称验证阻止路径穿越。附件位于共享 `assets/files/<UUID>/<原文件名>`，不引用用户原文件，不新增书签或系统权限。

复制先构建全部 RTFD / HTML / 结构 JSON / 纯文本，再更新剪贴板。RTFD 含实际文件字节，HTML 提供带文件名的数据链接；外部应用保留程度取决于其支持的格式。普通附件与音视频共用 32 MiB 富文本复制上限，超限使用导出，复制失败保留原剪贴板。库内结构粘贴生成新的块 UUID 并共用资产，缺失资产不得静默降级为文件名文字。

`MediaExport` 复用系统保存面板和后台原子导出，不改写源文件。双击只在明确操作后交给系统默认应用；文件导入时不执行或解包，复制保留原文件属性。

主要入口：`Core/NoteAttachment.swift`、`NoteContent` / `NoteFile`、`Editor/BlockTextCodec` / `NativeBlockEditor` / `NoteClipboard` / `MediaExport`。`NoteEditor.onAttachmentCommit` 沿用 NoteStore 保存；收纳摘要和类型筛选新增附件类型。

`FileAttachmentTests` 覆盖字节保留、重复文件独立资产、部分批次失败清理、目录 / 链接 / 超限拒绝、名称验证、编码 / TextKit 往返、撤销 / 重做、块粘贴、富文本真实字节、导出以及缺失文件不覆盖正文和剪贴板。

`check-library-window.py` 使用独立临时库和命名剪贴板，验证后台导入进入收纳共用编辑器，保持 NSTextView / UndoManager、保存重读和删除原文件后的独立性，并生成 `18-file-attachment.png`。本轮未用真实访达拖动、打开外部应用或操作用户笔记，离屏检查不能代替这些实机体验验收。
