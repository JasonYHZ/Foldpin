# 代码块边界与光标退出

2026-09-08，用户反馈光标无法离开代码块。

## 原因

纸片以代码块结束时，末尾没有普通正文块。原生 NSTextView 只能将空白区点击定位到已有文字的末尾，方向键在文档边界也不会创建新的结构化块。此前仅提供 ⌘Return 插入正文，鼠标和普通方向键缺少退出路径。

## 当前行为

- 代码块位于纸片末尾时，光标在代码最后一个字符之后继续按 ↓ / →，新建下方普通正文并进入。
- 代码块位于纸片开头时，光标在首字符之前继续按 ↑ / ←，新建上方普通正文并进入。
- 点击纸片首个代码块上方或末个代码块下方的空白，进入对应正文。代码内部留白、按住修饰键的选择和拖动仍交给原生编辑器。
- ⌘Return / ⌘小键盘 Enter 从代码任意位置进入后方正文，兼容 Caps Lock。紧邻已有普通正文时复用它；否则在代码之后插入正文，保留后面的其他块。
- 正常代码内回车继续插入代码换行。方向键在代码内部、已有相邻块间的移动，以及 Shift 扩展选择不创建额外块。

短纸片的编辑器高度至少覆盖滚动视口，让正文下方空白属于可点击的编辑区域。这只调整视图尺寸，不在打开笔记时补空行或改变内容。

## 数据与编辑约束

新建正文是明确退出动作产生的结构编辑，使用已有 replaceDocument 和同一个原生 UndoManager。原代码文本（包括尾换行、Unicode）、块 ID、语言与标记保留，退出后采用普通段落样式。已有正文之间的移动不产生正文写入或撤销记录。

只读状态和组合输入期间不创建块；异步代码着色继续按当前块 ID / 内容 / 语言校验，不影响新正文的光标。不能通过加载时附加隐藏换行、将代码改成普通文本或清空内容来实现退出。

## 验证

Xcode Debug 构建通过。

16 项相关检查通过，包含首尾四种方向键、空代码与尾换行、输入后撤销 / 重做、结构化 JSON 往返、已有正文、普通代码换行、选择扩展、空白区合成点击、只读 / IME、⌘Return / 小键盘 Enter / Caps Lock，以及斜杠菜单回归。测试使用离屏编辑器，未反复操作用户正在运行的窗口；真实点击命中与滚动到长代码末尾仍需新版使用确认。
