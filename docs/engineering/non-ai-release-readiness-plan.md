# 非 AI 功能收尾与私测准备开发方案

日期：2026-09-15\
状态：N1–N5 及 N7 的帮助、版本和本地反馈模板已接入 main 开发版。N6 资源回收尚未开放：共享来源、剪贴板及所有缓存会话的引用完整性仍无法证明。用户本次明确暂缓更新、发行与 AI 授权方案，因此 N8、签名分发和手动版本检查入口均不实施。真实登录启动、系统授权与 iCloud 双机验收仍待完成。

本轮实现范围、导入支持矩阵及验证记录见[非 AI 功能实现记录](non-ai-readiness.md)。下文保留阶段设计和验收目标，不代表每项实机验收均已通过。

当前存储实现：[资料库位置与 iCloud Drive 文件同步](library-storage.md)；原验收基线：[自定义资料库位置与 iCloud Drive 同步](library-location-and-sync-plan.md)。本文不重复实现迁移、不加入自动备份或 AI，也不把本文任务自动视为已获准发布、签名上传或删除用户文件。

## 1. 目标与优先级

让第一次接触 Foldpin 的用户快速开始，能带入已有资料，重启后继续使用，并能理解存储占用和获得新版本。保持“记 → 贴 → 收 → 找回”的产品中心，不扩展成大型笔记迁移器或磁盘清理工具。

| 阶段 | 内容 | 交付边界 |
| --- | --- | --- |
| R1 私测入口 | 最小引导、登录时启动、版本与反馈入口、签名分发验证 | 可交给首批用户独立安装使用 |
| R2 内容迁入 | Markdown 文件导入 | 复用原生块编辑，处理格式边界及本地资源 |
| R3 空间可见 | 分类用量、大附件定位 | 只读扫描，不删除资源 |
| R4 安全回收 | 本地无引用资源清理 | 引用完整性与撤销保护通过后单独开放 |
| R5 商店收费与更新 | StoreKit 试用／永久解锁，App Store 更新 | 按用户确定的商店渠道交付，无自建更新器 |

R1 不必等待 AI 或 iCloud 实机验收，但必须兼容已经接入的资料库加载、授权和切换流程。R4 依赖现有写入屏障、路径会话以及完整历史引用扫描；即使资料库放在本地，新格式仍保留修订历史。同步库的共享资产清理不属于本期。

## 2. 当前代码与需要调整的位置

- `FoldpinApp.swift` 中 `FoldpinSettingsView` 已有通用／外观／快捷键／数据与存储四页，使用独立的 `selectedTab` 整数状态；`ShortcutSettings.showShortcuts` 仅与快捷键页入口联动。N1 已增加通用页，并保留现有页面标识和独立选中状态。保留快捷键跳转和现有存储入口。
- `AppDelegate.swift` 已通过 `LibraryLocationController` 取得活动库，并接入保存屏障、切库和外部刷新回调。书签库可能异步加载；引导与登录启动应等待可确认的加载结果，不能把暂时没有条目当作首次安装。`openDefaultLibrary()` 已负责自动定位和升级默认库，不新增另一套目录选择或迁移流程。
- `Core/MarkdownPasteParser.swift` 已实现 Markdown 到 NoteContent 的转换；文件导入复用它，不引入 WebView 或第二套可写文档。当前默认 `importingRemoteImages: true`，文件导入必须显式配置资源策略，不能因解析就自动联网。
- `NoteLibrary` 当前新建路径先保存再显示；新增文档导入服务需复用相同持久化约束，并保持每张纸片／块 UUID 独立。
- `NoteFile`、媒体模型和 Store 通过共享 `LibraryPath` 跟随迁移位置，`LibraryLocationController` 用切换代次和 `LibraryPath.writeSerial` 防止应用过期快照。N4 已登记 LibraryFileActivity.imports，阻止导入中切库与外部快照应用；N5 的后台统计会校验路径、代次及修订快照，切库时取消结果。
- 图片、音视频、普通附件仍在共享 `assets/`。旧格式库彻底删除时移除纸片 JSON；带 `library.json` 的新格式库写入空载荷删除修订，保留旧修订和资产。正常纸片、最近删除、冲突副本、历史修订以及撤销可能引用同一资源，不能把“删除后还有文件”判定为垃圾。
- 新格式的当前数据来自 `revisions/notes/` 与 `revisions/collections/`；迁移保留的旧 `notes/` 等文件是恢复材料。`LibraryDisk.snapshot` 只返回当前修订视图，其默认读取还可能生成冲突副本／合并修订，因此不能直接作为只读用量扫描或完整历史引用扫描器。`library.json` 的基线和父修订关系目前不支持自动压缩或清理。
- `FoldpinLocalState/` 保存本机书签、迁移日志、目录锁和按库 UUID 组织的桌面状态，不属于可清理缓存。设置中的位置选择和默认位置恢复已实现，N5 只扩展现有数据与存储页。
- `NoteExport` 已有 Markdown／HTML 导出、资源打包；这是导入测试的样例来源，不代表所有导出结构都能无损反向解析。

以上为源码核对，不是新增测试结果。具体实现开始前须核对最新工程及 AGENTS.md，保留其他任务改动。

## 3. 首次使用说明纸片

2026-09-15 用户确认：首次打开直接给一张简短操作说明纸片，不再提供独立欢迎页或引导步骤。

### 首版体验

首次手动启动且新安装的默认资料库正常可写时，直接保存并打开一张普通可编辑、可收纳、可删除的纸片，用五条短说明介绍记录、添加内容、贴放、收纳与更多操作；保留一个待办示例及新建／操作快捷键。

正文保持简短，不展开完整功能手册；不自动申请麦克风权限、配置 AI 或开启登录启动。

### 状态与恢复

- 完成状态和说明 UUID 记录在本机偏好；通过正式保存路径成功创建后才标记完成，失败可重试。
- 已有库、主动空库、manifest／历史修订及仅剩删除记录均属于已有资料证据；书签恢复中、库不可读或登录后台启动不自动添加说明。
- 帮助菜单及通用设置提供「使用说明」，复用已创建纸片及其编辑；已软删除时定位最近删除，永久删除后只在用户明确打开帮助时生成新 UUID。
- 用户编辑、收纳或删除说明后，后续启动不自动覆盖或补回。正文语言和快捷键为创建时快照，明确以当前设置为准。

`GettingStartedNote` 负责内容和幂等保存，AppDelegate 使用现有 PaperWindowController 打开；没有额外欢迎视图或编辑器。

## 4. 登录时启动

设置“通用”页提供“登录时启动 Foldpin”，默认关闭。通过 `SMAppService.mainApp` 注册／注销；以系统实际状态驱动界面，不能只切换一个 UserDefaults 布尔值就显示已开启。

- 开启成功：显示已开启。需要系统批准：显示待批准，提供打开系统登录项设置的入口。失败：显示原因和重试，不伪造成功。
- 用户从系统设置关闭后，应用重新激活时刷新状态；不自动再次注册。
- 登录启动被动恢复既有桌面纸片，不抢焦点，不弹欢迎或收纳窗口，已收纳纸片不全部展开。
- 恢复遵守当前资料库错误与授权状态；目录不可用时不创建替代库，等待主动打开后处理。
- 启动方式识别需按公开 API 和真实签名应用验证；不能只靠不可靠的命令行参数假设区分手动／登录启动。
- 注册针对用户实际安装的应用；从临时构建目录、DMG 或移动后的应用运行时给出安装指导，不静默复制程序、写 LaunchAgent 或注册重复辅助进程。

建议 `LoginItemSettings` 封装状态与错误；与现有全局快捷键注册保持独立，不引入新的系统权限。

## 5. Markdown 文件导入

### 入口和范围

“文件 → 导入 Markdown…”以及收纳窗口的新建菜单提供同一入口，支持选择一个或多个 `.md`／`.markdown` 普通文件，每个文件生成一张已收纳纸片。单文件成功后选中并编辑；批量成功后显示结果列表，不弹出几十个桌面窗口。

首版不接管正文已有拖入文件／粘贴附件行为，不自动更改默认文件关联；也不递归导入文件夹、Obsidian 库、ZIP 或任意 HTML。

建议初始上限：单个 Markdown 5 MiB，每批最多 50 个、正文合计 25 MiB、需复制的本地资源合计 512 MiB。数值为实现保护提案，需在代表性测试后校准；超限解释原因，不截断正文。

### 内容与资源

1. 后台读取，支持 UTF-8（含 BOM）及可明确识别的带 BOM UTF-16；其他编码提示用户转换，不用有损解码产生乱码。
2. 复用 MarkdownPasteParser 及既有块模型。标题、列表、待办、代码、引用、表格、链接按实际支持范围转换；无法完整表达的 YAML front matter、嵌套结构、HTML、脚注、Wiki 链接等保留原始文本并报告降级，不能默默删掉内容。
3. 空文件导入为空白纸片并说明；普通文字文件仍导入为段落。正文没有标题时不擅自插入文件名当正文；结果列表用来源文件名说明来源，纸片继续沿用首行标题规则。
4. 相对路径以源文件所在目录解析。但选中一个文件不代表沙盒已授权其所有相邻资源；若需读取附件，要求用户通过目录选择器授权明确的资源根目录。取消授权仍可选择保留未解析链接，结果明确提示。
5. 对本地图片复制原件并按现有图像流程生成预览。其他本地媒体／文件链接可保留链接，或在明确支持的转换路径中导入现有附件块；首版必须列明实际支持矩阵。
6. 路径规范化后必须位于授权资源根目录内；拒绝符号链接越界、路径穿越及未经授权的绝对路径读取。源文件与原资源不移动、不修改。
7. 远程图片默认保留地址或明确占位，不自动请求；网络下载留给用户后续主动操作。不执行 HTML、脚本、命令或自定义 URL scheme。
8. 本地资源导入后属于 Foldpin，原文件移走仍可使用；缺图、资源超限、权限失败在提交前让用户选择跳过该文件或保留链接，不静默省略。

### 提交、取消与重复

使用独立 `MarkdownFileImportCoordinator`：解析 → 资源暂存 → 内容校验 → 保存新文档 → 发布库条目。每张文档独立事务，批量显示成功／跳过／失败数；一个失败不宣称全部成功。原子保存成功前不显示已导入条目。

任务须登记到资料库文件操作屏障，绑定库身份和本次任务的路径／切换代次；迁移或切库须等待它完成或安全取消，提交前再检查身份和可写状态。沿用 `NoteLibrary` / `NoteFile` 的新建路径，让新格式自动产生修订，不直接写旧 `notes/<UUID>.json`。本轮已新增 `LibraryFileActivity.imports` 计数与取消路径，和既有导出／编辑器任务检查一起使用。

取消停止未提交项目，已成功项目保留并列出；只清理本任务未提交且无引用的暂存资源。再次明确导入同一文件允许产生副本，界面说明；同一次失败重试通过任务 ID 保证不重复提交成功项目。

全批导入不伪装成正文 UndoManager 的一次撤销；已导入纸片可从结果列表选中并移到最近删除。编辑器内既有撤销不受影响。

## 6. 存储空间管理

### R3：先做只读用量

扩展已经存在的 `LibraryStorageSettingsView`，保留当前库位置、更改位置、打开已有库和使用默认位置入口，新增扫描状态、最近扫描时间及刷新按钮，不重复实现存储位置功能。

分类：当前正文与集合修订、历史修订、图片、音频、视频、普通附件、迁移保留文件／历史备份，以及应用本机数据和可确认的缓存。当前修订与历史修订使用互斥分类，同一资源文件只计入总量一次。最近删除、冲突副本和历史引用作为关联说明，不再把资源大小重复加到总量。`FoldpinLocalState` 中的桌面状态、书签、迁移日志和目录锁标为本机必要数据，不归为可回收缓存。

同时列出较大的资源、大小、类型、引用它的纸片，允许定位纸片或导出。无法确定引用归属的项目显示待检查，不立即提供删除按钮。主视图以资料库逻辑大小为主，本机实际占用在系统可可靠提供时单独显示；iCloud 未下载资源不能按 0 字节宣称不占空间。

扫描后台分批进行，可取消；不解析或播放整个媒体、不主动下载云端资源。不要调用会协调生成新修订的默认 `LibraryDisk.snapshot`，也不要调用会发起下载的 `pendingResources` 来实现“只读统计”。应采用不写入、不请求下载的目录／元数据遍历；本机已有的修订可解码以建立关联，历史扫描不能只取每个对象的当前头部。目录不可用或资料未齐时显示统计不完整，不能把未下载或未能解析的历史文件计为零。扫描绑定库身份、路径代次和观察到的修订状态，换库／迁移或相关状态变化后废弃旧结果。

### R4：本地无引用资源回收

清理入口第一阶段仅对能够明确证明未共享、且完整引用检查通过的本地库开放。文件夹当前在本地、不是 iCloud 路径，或当前没有联网，都不足以证明它从未与其他设备共享；现有实现没有库的共享来源记录，N6 必须先明确识别依据，无法确认则只提供统计。先显示可回收候选和字节数，用户确认后操作；不自动定时清扫。

必须建立全库引用保护：正常纸片、最近删除、冲突副本、所有保留的非空纸片修订、所有保留会话的 UndoManager 可能恢复的资源、活动导入／录音、导出快照及剪贴板结构复制所需资源。按实际库身份和资产目录归属检查，不能因切到另一资料库就忽略缓存会话。若不能完整枚举撤销引用，则该会话曾使用的资产全部保护到会话结束；不能为清理清空撤销。

删除记录的载荷为空，不表示祖先修订不再需要资源；被新修订替代的旧修订也继续受保护。即使是确认未共享的本地新格式库，只要任一保留修订引用该资产，就不进入回收候选。本期不删除／截断修订、父关系、初始基线或删除记录，也不借资源清理实施历史压缩。

剪贴板可能跨退出保留资源引用：需先明确结构复制的有效期和资源租约／持久保护策略；未解决前，相关资源不进入可回收清单。迁移保留的旧 `notes/` 和历史备份若引用 `assets/`，也必须加入保护；无法解析的笔记／历史修订、未知版本、损坏记录、缺失父修订／初始基线或不完整扫描意味着不能证明无引用，应阻止该批资源清理。

流程：完整扫描 → 计算候选 → 展示确认 → 获取写入屏障并复查全部历史与会话引用、库身份／代次和修订状态 → 将候选移入本机库内受控隔离区 → 持久化清单 → 恢复操作。清理失败保留原件或隔离清单，支持重试和还原。

隔离仍占磁盘，界面不得显示空间已释放。真正删除隔离内容是另一个明确确认的动作，再次检查引用；删除成功后才报告实际释放。实现若暂不提供隔离，则不得宣称清理可撤销。

同步库不做资产回收：其他设备的离线分支、删除记录、冲突版本未必已到达本机。未来支持须结合共享修订保留协议另立方案，不通过等待固定天数假定所有设备已同步。迁移保留的源目录、用户导出文件及整个资料库不属于清理目标。

## 7. Mac App Store 分发、7 天试用与永久解锁

2026-09-14 用户最新决定：正式渠道以 Mac App Store 为目标，7 天试用、一次购买永久解锁，后续更新不另收费。此节替代此前官网分发／独立更新器提案；不实现 Sparkle、自建更新服务器或应用内替换程序文件。详细收费状态机见 [App Store 买断与试用方案](app-store-purchase-and-trial-plan.md)。

- 应用免费下载；按 Apple 非订阅试用规则配置免费非消耗型“7-day Trial”商品，另设付费非消耗型永久解锁商品。不用自动续订订阅模拟买断。
- 试用开始前显示期限、结束后限制、永久解锁价格以及不自动扣费。结束后保留查看、复制、导出和已有数据，不以锁定数据迫使购买。
- StoreKit 2 在设备端验证交易、恢复购买和处理撤销；首版不建 Foldpin 账号、授权服务器或支付后台。首次领取、购买、恢复及获取更新仍可能需要连接 Apple。
- 更新通过 App Store 审核和分发；关于／帮助提供“在 App Store 中查看”，不伪装成应用自行检查或安装更新。保留本地版本／构建号和更新说明。
- 发布前准备 App Store Connect 商品、沙盒配置、隐私政策、支持页面、商店截图和审核说明；走商店签名／归档流程。私测优先 TestFlight，测试购买不转成正式购买权益。
- 系统和架构范围按实际验证确定；当前 macOS 26.5 是工程配置，不自动成为最终承诺。沙盒下逐项验收自选资料库、登录项、全局快捷键和媒体权限。
- 反馈由用户主动打开已确认支持地址或复制模板。诊断预览仅含版本、架构及非敏感错误代码，不含正文、附件、密钥或完整路径，不自动上传。
- 永久更新在本方案中指本应用后续发布的更新不再收升级费；不自动意味着无限期维护、所有未来系统均兼容或赠送第三方付费服务。商店文案应清楚，不能擅自收窄用户已购买权益。
