# 区块换行、占位提示与下一阶段编辑能力

2026-09-08，按用户提供的 [空块占位截图](../design/native-block-menu/reference-empty-blocks.png)、[块操作截图](../design/native-block-menu/reference-block-actions.png)与换行 / 占位 / 块编辑问题整理。

## 参考依据与边界

Notion [快捷键说明](https://www.notion.com/help/keyboard-shortcuts)明确区分普通 Enter 与 Shift+Enter：后者是在原区块内换行；选中块后还可用快捷键复制、移动和删除。[编辑基础说明](https://www.notion.com/help/writing-and-editing-basics)说明左侧加号用于插入，六点手柄可拖动，点击手柄可转换、复制、移动和删除块。

用户截图中的灰色「标题 2 / 标题 3」表现为空块占位提示，第二张图展示整块选中与块操作菜单。此轮依据截图与官方文档对照，没有进入用户的 Notion 页面逐项敲键测试；下面的完整行为矩阵是 Foldpin 的当前规则，不声称逐项复刻 Notion 未公开的细节。

## Foldpin 当前换行规则

| 当前内容 | Enter | Shift+Enter |
| --- | --- | --- |
| 正文 | 按光标位置拆分为两个正文块 | 同块换行 |
| 有内容的 H1–H4 | 标题保留光标前内容，后方进入正文 | 同标题块换行 |
| 空 H1–H4 | 当前块退回正文，保留 ID | 同块换行 |
| 非空项目列表 / 有序列表 / 待办 | 新建下一项；新待办默认未完成 | 同项换行，不重复项目标记 |
| 空项目列表 / 有序列表 / 待办 | 当前块退回正文 | 同项换行 |
| 非空引用 | 延续引用块 | 同引用块换行 |
| 空引用 | 当前块退回正文 | 同块换行 |
| 代码 | 留在代码中换行 | 留在代码中换行 |
| 图片 | 后方插入正文 | 后方插入正文 |

代码继续支持 ⌘Return 退出以及文档边缘方向键 / 点击空白退出，见[导航规则](code-block-navigation.md)。原有结构转换与原生撤销栈保持一致；组合输入期间不自动转块。

正文块内的软换行使用 AppKit 的 U+2028 行分隔符，代码内使用 LF。依据 Apple [行与段落边界说明](https://developer.apple.com/library/archive/documentation/Cocoa/Conceptual/Strings/Articles/stringsParagraphBreaks.html)，这是原生 insertLineBreak 的文本表示。它保存在同一个 block.text 中，JSON schema 不变，不使用隐藏占位字符模拟换行。

## 空块占位提示

标题现扩展到四级，`###` / `####` 加空格分别创建 H3 / H4，菜单也可直接选择或转换。H1–H4 字号分别为 23 / 18 / 16 / 15 点半粗体。新增 `heading3` / `heading4` 保存值，H1 / H2 仍沿用 `heading` / `subheading`。下文回车规则用于普通文字编辑；整块选中时 Enter 仍先进入该块编辑状态。

空白纸片的提示与区块提示使用同一套原生绘制。用户反馈重叠后，检查发现 ContentView 仍保留原先的 SwiftUI「Jot something down…」空状态，与新的原生正文提示叠在同一位置；现已移除外层旧提示及无引用的翻译键。此问题发生在 SwiftUI 与 AppKit 组合界面，之前单独绘制 PaperTextView 的离屏检查未覆盖外层重复显示。

空 H1–H4 显示相应标题级别；列表显示「列表项」、待办显示「待办事项」、引用显示「引用」、代码显示「输入或粘贴代码」。普通空正文仅在当前编辑块显示「输入文字，或用 / 选择区块」，避免满屏重复提示。

文字依据 TextKit 2 的插入位置与当前块字体绘制，尊重当前语言和明暗模式，不插入 NSTextStorage；不进入保存、复制、撤销、折叠标题或搜索正文。实际输入后消失，活动组合输入处不绘制提示。图片保留已有文件选择流程，不创建虚假的附件占位数据。

代码占位文字采用所选代码主题的注释颜色，与纸片明暗独立，避免亮色纸片搭配暗色代码主题时提示不可读。

## 菜单与中文输入

菜单右侧仅显示 `#`、`##`、`-`、`[]`、`"`、三个反引号等符号，按用户最新要求去掉「+ 空格」。实际触发条件继续是行首输入前缀后按空格或回车（回车用于代码围栏和分隔线）。

代码围栏接受三个 ASCII 反引号、三个中点 `···` 或三个全角反引号 `｀｀｀`，可带 java / python / js 等已有语言。三种写法都使用同一套转换与撤销。两点、四点、混合符号、句中内容、粘贴内容和输入法组合文本不自动改为代码块；不把所有标点统一替换，代码正文保持原样。

## 建议继续做的原生块编辑

Foldpin 已有带 ID 的结构化块、转换、按键移动和复制能力。建议继续增强操作入口，沿用 NSTextView + TextKit 2：

1. 块侧边手柄与加号。按块 ID 定位；点击菜单提供转换、创建副本、删除和上下移动。先支持单块选中、明确背景反馈，不借用其他块的光标位置执行操作。
2. 单块拖动排序。显示落点线，拖动只改变顺序，放下后作为一次原生可撤销操作；长块与视口边缘自动滚动要独立验证。
3. 再加入多块选择 / 批量操作及必要的嵌套列表。普通表格已随后实现，见[列表、分隔线与表格](lists-dividers-tables.md)；页面和页面链接仍需要额外内容模型与产品范围决策。

用户随后确认开始第一步：六点手柄、单块选中与操作菜单已实现，见[单块操作说明](block-actions.md)；拖动排序和多块选中仍为后续范围。不要照搬 Notion 的所有快捷键：Foldpin 的 Esc 已用于关闭浮层 / 收纳纸片，新增块选择后应先取消选择，再回到既有行为。删块须支持撤销，删除图片块保留附件供撤销，最后一个块删除后保留一个空正文。

原生实现可以复用现有文档与 AppKit 控件；不需要改为 WebView 或替换语法引擎。主要成本在选区、拖动落点、IME、撤销与跨块复制的一致性，而不是绘制六点图标。
