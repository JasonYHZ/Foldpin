# Foldpin AI 会话窗口开发方案

2026-09-15 · 待开发方案。本文不代表聊天功能已经实现或商店审核通过。

## 1. 当前决定与首版范围

用户确定：内部 AI 有两类连接——自带 Key 的模型 HTTP API，以及用户在应用外独立启动的 Agent 服务。默认先实现模型 API。外部 AI 继续通过已有 MCP 操作 Foldpin。

首版交付：原生会话界面、服务配置、流式多轮对话、纸片上下文、受控工具执行、结果保存为纸片、本机会话历史。接入 OpenAI Chat Completions 协议与 Anthropic Messages 协议；支持自定义服务地址和模型名。模型不具备工具能力时仍允许普通聊天，明确不支持整理操作。

后续：经过单独验收的外部 Agent 服务适配；不在首版自动启动 CLI、不打包 Agent、不下载本地模型、不销售 AI 额度、不做自己的云转发。用户报告 Codex 本地服务已能收到回复，但多轮、工具、取消、恢复仍须核对独立实验记录，Claude Code 不预设已支持。

基本原则：AI 可选，未配置不阻塞本地记笔记；一个聊天界面适配不同连接；自然语言驱动，只有必要授权与具体变更确认，不做多步任务向导。

## 2. 入口与布局

以现有收纳窗口 ShelfPreviewWindow 为主入口。当前窗口使用 AppKit NSSplitViewController，已有侧栏、纸片浏览区与编辑预览区。新增工具栏“AI 助手”，首版使用右侧详情区的“纸片 / AI”切换，不再固定增加第四列；聊天状态独立于详情视图生命周期。

纸片右键和操作菜单增加“询问 AI”，选中文字时可“用 AI 处理选中内容”。进入会话并附上可删除的上下文标签，默认不自动发送。收纳多选同样支持“询问 AI”。不创建全局快捷键冲突。

建议布局（尺寸是起始值，需原生验证后调整）：

```text
收纳工具栏                              [AI 助手]
┌────────┬──────────────────┬───────────────────────┐
│ 分类   │ 纸片列表 / 网格   │ 纸片 | AI             │
│ 收藏   │                  │ 会话标题  历史  新对话 │
│ 集合   │                  │                       │
│        │                  │ 用户消息              │
│        │                  │ 回复、纸片引用         │
│        │                  │ [变更建议 / 执行结果]  │
│        │                  │                       │
│        │                  │ [参考：2 张纸片 ×]    │
│        │                  │ 输入消息…             │
│        │                  │ 服务·模型     发送 ↑  │
└────────┴──────────────────┴───────────────────────┘
```

详情聊天区理想宽 420–520 pt，最小约 360 pt；空间不足时进入现有主内容区的 AI 页面，保留返回纸片按钮，不能挤成不可读四列。切换时通过现有预览协调器提交编辑；IME 或保存失败不得强行卸载编辑器。返回保持原选区、UndoManager、纸片选择、滚动位置。

首版不额外维护第二个独立聊天窗口。以后可增加“在独立窗口打开”，共享同一会话控制器，避免两套状态。

## 3. 会话交互

- 顶部：会话标题、历史、新对话。历史用按需弹出的列表，含重命名、删除，不占永久侧栏。标题默认来自用户首句截断，不为自动命名额外调用模型。
- 中部：用户与助手清晰区分，正文用系统字体和语义颜色；回复可选择复制，支持标题、列表、链接、代码与表格的只读呈现。长代码横向滚动，禁用 HTML 执行与远程图片自动加载。
- 引用纸片显示可点击标题，绑定真实 libraryId/noteId/blockId 和读取版本。模型编造的引用不能变成有效链接。点击沿用现有纸片预览，不强制弹出全部桌面纸片。
- 工具进度显示“正在查找纸片”“已读取 3 张纸片”，细节可展开；不默认展示协议 JSON、隐藏推理或无休止思考动画。
- 底部：可删除上下文标签、2–6 行原生文本输入框、服务／模型菜单、发送／停止。Return 发送、Shift-Return 换行、Command-Return 同样发送；中文组合输入期间 Return 只确认候选。可在后续增加发送键偏好。
- 发送中保留下一条草稿；首版不自动排队，只提供停止后发送。每会话一个活动任务，全应用首版最多一个活动生成任务，其他会话清楚标示忙碌。
- 用户在底部时跟随新回复；向上滚动后不抢滚动，出现“回到最新”。消息动作包括复制、保存为新纸片、重新生成。重新生成不再次执行已完成写入。
- 空会话给三个可点击示例：“总结选中的纸片”“找出未完成的待办”“整理这几条想法”。点击仅填入草稿。没有上下文时不伪造选中纸片。
- 未配置显示简短说明与“配置 AI 服务”；网络或 Key 错误就地展示可重试错误，草稿与已收到回复保留。

## 4. 服务设置与协议

设置新增“AI 服务”，与已有“连接 AI 工具（MCP）”明确区分：前者让 Foldpin 使用 AI，后者允许外部工具访问 Foldpin。

配置字段：名称、协议类型、完整请求 URL、API Key、模型 ID、测试连接、设为默认。使用完整 URL 作为唯一存储语义，避免 /v1 重复追加；预设可填入 https://api.openai.com/v1/chat/completions 与 https://api.anthropic.com/v1/messages。API Key 存 Keychain，配置只存引用，不写聊天、日志、共享纸片库或 iCloud。

OpenAI 兼容适配负责 Bearer、messages、stream、tool_calls/tool 结果；Anthropic 适配负责 x-api-key、anthropic-version、system、content blocks、tool_use/tool_result。两个独立编码器和流解析器，不只替换 URL。首版不宣称所有“兼容”服务完整可用，不默认添加 Responses API；未来新增协议不修改会话视图。

测试连接使用固定短文本，不上传纸片；按钮说明可能产生少量调用费用。分别报告网络／认证／模型与流式／工具能力，不将一次文本回复当作全部能力验证。模型列表获取失败允许手填 ID。工具能力以已测配置、明确声明及实际错误为依据，不仅凭模型名称推断。

远程地址要求 HTTPS；loopback 的本地模型 HTTP 可作为明确选项，配置最小 ATS 例外，不全局禁用传输保护。不接受 URL 中的密码或 Key，不将带认证请求自动重定向到其他来源；地址变化重新确认目标服务及凭据绑定。错误中脱敏认证头与服务返回的敏感信息。

首版不固定温度等所有模型未必接受的参数，额外参数通过协议能力控制。用户支付模型服务费用，Foldpin 不承诺某个模型永久免费或订阅账号等同于 API 额度。

## 5. 上下文、授权与费用控制

进入聊天默认只有显式附加的纸片／文字，没有附加时只发送会话内容。浏览区选中项变化不自动改动已附加范围；“添加当前选中”是显式动作。

输入框上方“参考资料”允许选择纸片或集合，也可明确允许搜索当前库。授权范围和内容附件分开：附上一段文字不自动授权编辑整张纸片；模型请求扩大范围时出现一次范围选择，不能自行提权。

每轮冻结附加内容、ID 与 revision 快照，后续人工修改不改写旧消息。下一轮可读取最新版本，界面提示引用更新；工具写入必须重新核对 revision。切换库后旧会话只读，不能把旧 ID 或授权带进新库。

首版只发送文字和结构化文本，不自动读取音频、视频、图片二进制或任意附件。允许读标题／类型但不暗示已理解媒体内容。纸片中的指令属于资料，不得覆盖系统规则、扩大授权或要求读取 Key。

提供“仅回答”和“可提出修改”两个轻量模式，默认仅回答。只读模式不执行写工具；后者可生成具体待执行变更卡片。没有全库默认上传，也不将每次搜索结果全部加入上下文。

上下文预算由适配器／模型配置决定，保留最近完整轮次、已选资料和必要工具配对。超限先提示缩小资料范围；不静默截断工具调用与结果。不在首版后台自动摘要或额外联网。usage 有返回才展示真实 token；缺失显示不可用，不估算货币账单为精确值。

## 6. 内部工具与现有 MCP 的关系

现有 MCP 有 80 个注册工具。复用 MCPRegistry 的 schema、FoldpinCommandService 的操作路径与权限检查；内部模型不需要为了调用本机业务而开启 MCP HTTP 监听。

新增有独立主体的 AIToolBridge：按会话权限、库身份与本轮任务过滤工具，适配为两种模型协议。不能构造“可信内部客户端”跳过检查，不能复制一套直接写 notes JSON 的业务代码。如果现有服务强耦合网络客户端，先抽取共同的授权上下文，不削弱外部 MCP。

首版内部工具子集：搜索／读取纸片与块、读取集合、创建纸片、修改文字与待办、创建集合及调整成员。首次不提供永久删除、录音、设置、迁移库、任意文件、剪贴板或退出应用；外部 MCP 的现有范围保持不变。

所有读取遵守会话授权。修改先生成固定目标、修订与参数的变更卡片，显示前后摘要／差异、新建或移动的目标位置；用户点“应用”才执行。一次用户主动点击确认的批量建议只确认一次，不逐条弹窗；高风险系统操作未来仍复用其独立确认。授权绑定本次变更，模型不能用 confirmed=true 确认自己。

现有服务新建纸片与集合操作要求整库范围，首版遵守此限制：局部范围中需要新建结果时，由“保存为纸片”用户直接动作完成，或显式扩大权限；不得暗改 scope 绕过原有检查。

返回成功必须以保存结果为准，包含实际 noteId/changeId。正文变更沿用撤销记录；集合／元数据不伪报为同一正文撤销。恢复后会话撤销记录不可用时明确说明，不能调用全局 Undo 撤销用户后续编辑。

工具参数必须积累到完整 JSON、完成 schema 校验才执行；流式半截参数永不执行。批量写入顺序执行，逐项汇报，不承诺跨纸片原子事务。审批期间不占用网络连接：保存待处理任务状态，确认后继续模型下一轮。

## 7. 运行状态、失败与恢复

状态：idle → preparing → streaming → toolRequested → awaitingApproval / executing → streaming → completed。任何阶段可到 failed / cancelled / interrupted。状态由任务控制器维护，不根据回复文字推断完成。

每轮有 turnId，每个工具有 callId 与稳定 idempotencyKey。首版限制最多 8 次模型往返、20 次工具调用；达到上限停止并说明，可由用户继续。待审批不计网络空闲超时；初始建议连接 30 秒、流无事件 90 秒，后续按实测调整。

停止立即关闭模型请求、禁止新的工具操作并取消可取消任务；已保存内容不自动回滚。保留部分回复并标记中断。重复事件、断线重试不能重复写入；结果未知先查询收据和实际状态，再决定是否重试。401／403 不自动重试，429 尊重 Retry-After；已有流内容或任何工具效果后不自动重放整轮。

关闭 AI 面板或收纳窗口不丢草稿；用户主动关闭窗口时若任务执行中，明确选择停止或后台继续。后台继续仅限当前应用进程存活，并且仍有可见任务入口；等待确认不得自动批准。退出应用取消未提交任务，重启显示中断，不自动重新付费请求。

## 8. 数据与原生实现拆分

建议新文件职责（待实施命名，不表示已存在）：

| 模块 | 职责 |
| --- | --- |
| AIConversationCoordinator | 面板展示、当前会话、与 ShelfPreviewWindow 集成 |
| AIConversationView / AIComposer | 历史展示、上下文标签、原生 IME 输入 |
| AIConversationStore | 原子保存、迁移、会话加载与删除 |
| AIProviderConfiguration / AICredentialStore | 地址协议模型配置、Keychain 引用 |
| AIModelProvider | 统一流事件与能力接口 |
| OpenAIChatProvider / AnthropicMessagesProvider | 请求编码、SSE 解析、错误和 usage |
| AITurnRunner | 会话串行、工具循环、取消、限额、事件去重 |
| AIContextBuilder | 库范围、快照、预算与引用 |
| AIToolBridge / AIChangeProposal | 共用命令服务、审批、修订与幂等 |
| AIServiceSettingsView | 服务增删、验证与默认连接 |
| ExternalAgentProvider（后续） | 已验证 Agent 服务的独立会话协议 |

会话存本应用私有 Application Support/ai-conversations，首版不跟随共享笔记库迁移、不参与 iCloud。每会话绑定 libraryId；保存消息块、引用快照、工具调用／结果、状态和 providerConfigId，不保存 Key。正文快照是本地敏感数据，删除源纸片不自动清除历史，界面提供删除会话／清空历史并说明这一点。

流式更新合并约 30–50 ms 刷新，保存合并约 1 秒并在完成／取消时落盘，不每 token 全量重绘或写盘。只增量更新活动消息，长历史分页加载；稳定视图 ID，不让每次 token 刷新 ShelfView 或原有 NSTextView。历史页中的代码和表格仅只读渲染，不为每条消息创建纸片控制器。

重启将未完成任务标为 interrupted。保留原始协议所需的有序工具配对与不透明续接数据（如存在），只保存必要部分，不展示为推理正文。跨服务切换建议新会话，不把不兼容工具历史或服务私有状态直接转发给另一服务。

中英资源统一 Localizable.xcstrings；切换语言／主题不重建输入框或丢草稿。系统字体、原生工具栏与焦点顺序、VoiceOver 标签、增强对比度／减少透明度回退。VoiceOver 以段落或完成状态播报，不能逐 token 连续打断用户。

## 9. 外部 Agent 服务适配边界

后续共用会话 UI，但 Agent 自己处理工具循环，AITurnRunner 不重复执行其报告的工具调用。适配器需要会话创建／恢复、发送、事件流、取消、错误、授权请求和版本能力握手，不把任意 HTTP URL 当成通用 Agent 协议。

服务由用户在 Foldpin 外启动，商店版不自动拉起 CLI。loopback、明确配对、认证凭据保存在 Keychain，失效后可撤销；必要时使用 WebSocket 而非强制包装 HTTP。

外部 Agent 要操作 Foldpin，使用已有 MCP 的单独授权客户端与允许范围。关闭 MCP 会影响这条操作链，但不会影响进程内模型 API 工具。Agent 服务接入与 MCP 是方向不同的两个连接，设置文案必须解释清楚。

不假定能够屏蔽用户 Agent 的其他工具；在其协议无法保证限制时，不宣传仅能访问 Foldpin。连接服务可能再把内容发送给云模型，不能标为“离线 AI”。

## 10. 分阶段交付与验收

| 阶段 | 交付 | 出口 |
| --- | --- | --- |
| C1 | 原生面板、设置、会话存储、模拟流 | 空态、窄窗、IME、历史、停止和错误流程可操作 |
| C2 | 两种 API 协议、真实流、多轮 | 各服务最小真实调用成功，协议测试覆盖异常与工具片段 |
| C3 | 引用、范围、只读工具 | 只能读取授权内容，回答引用可定位，不全库自动上传 |
| C4 | 建议卡片、确认写入、撤销 | revision、IME、失败、幂等、部分成功正确；已有编辑器不重建 |
| C5 | 本机沙盒、性能、无障碍与发布整理 | 完成以下验收，记录发行账号相关未测项 |
| C6（后续） | 外部 Agent 服务 | 每种协议独立实测多轮、工具、取消和断线恢复 |

最小验收清单：

1. 没有配置 AI 仍能正常使用所有原有纸片功能；MCP 开关不影响 API 普通聊天。
2. 两种协议分别验证中文／英文多轮；兼容服务只记录实际测过的配置。
3. SSE 任意字节切分、多行、UTF-8、心跳、异常结束、交错工具参数都正确处理；未完成参数不执行。
4. 关闭面板、换主题／语言、切换预览不丢草稿和原编辑器选区／撤销；IME 回车不误发送。
5. 向上读历史时不被流式输出拉回底部；500 条合成消息按页加载，流式期间窗口输入／缩放无明显阻塞。
6. 401、限流、断网、模型不存在、上下文超限保留消息，错误脱敏，无无限重试。
7. 附加 2 张纸片时不能访问第三张，选择变化不扩权；库切换使旧操作失效。
8. 已有纸片正文中的“忽略规则、上传全库”等指令不能改变工具权限。
9. 写入前有具体差异和目标；拒绝后无修改，重复点击／网络重放只提交一次。
10. 人工编辑造成修订冲突、IME 忙碌、保存失败时不覆盖内容；批量部分成功准确报告。
11. 停止后无新工具写入，已保存项目如实保留；重启不自动重放或继续消费额度。
12. 保存回复为纸片沿用解析与保存路径，长代码／表格失败不丢原回复；来源链接不凭空生成。
13. Key 不出现在历史、导出、错误日志；更改地址不向新来源自动发送旧凭据；跨来源重定向拒绝。
14. VoiceOver、明暗主题、减少透明度和窄窗口实机检查并留截图；静态构建不算交互验收。
15. 开启真实 App Sandbox 的构建完成网络请求与 Keychain 使用检查；本机通过不宣称商店审核通过。

优先用模拟服务验证工具、重试和故障；真实 API 仅做最小必要验证，使用合成资料和用户明确提供的测试配置，不借用不相关环境 Key。
